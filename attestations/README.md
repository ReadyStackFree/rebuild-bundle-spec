# Attestations on ReadyStack images

ReadyStack attaches three signed in-toto attestations to each release image on Docker Hub (`docker.io/readystack/*`),
on both digests of a release: the image index the release tag names, and the linux/amd64 image manifest that a
ReadyStack Rebuild Bundle rebuilds. They are signed with the ReadyStack release key and recorded in the public Sigstore
transparency log (Rekor). They are stored in cosign's attachment format, a `sha256-<digest>.att` tag beside the image.

| Predicate type | What it is | Where it comes from |
|---|---|---|
| `https://slsa.dev/provenance/v1` | SLSA v1 provenance: the inputs of the build, each named by hash | Written by ReadyStack after its release gate, from the records in the release archive. See [PROVENANCE.md](PROVENANCE.md) |
| `https://spdx.dev/Document` | An SPDX 2.3 SBOM of the image | The SBOM BuildKit generated at build time and attached inside the image index, signed again here unchanged |
| `https://slsa.dev/verification_summary/v1` | A SLSA Verification Summary Attestation (VSA) of ReadyStack's release gate | Written when the release gate passes, at publish. See [RELEASE_GATE_POLICY.md](RELEASE_GATE_POLICY.md) |

Releases published before 2026-10-20 carry the first two only: the release gate ran before this policy was published, so
there is no VSA to sign for them. A release whose archive holds no record that binds it to the published image (some
releases made before the current release engine) carries no provenance, because ReadyStack does not write provenance
it cannot support from a record.

## Verify

The release key is published at <https://readystack.dev/keys/cosign.pub> (fingerprint: the first 16 hex characters of
the sha256 of the DER public key, `04daa92344a52dbc`).

```
curl -fsSLO https://readystack.dev/keys/cosign.pub
cosign verify-attestation --key cosign.pub --type slsaprovenance1 readystack/<product>:<release-tag>
cosign verify-attestation --key cosign.pub --type spdxjson        readystack/<product>:<release-tag>
cosign verify-attestation --key cosign.pub --type https://slsa.dev/verification_summary/v1 readystack/<product>:<release-tag>
```

cosign 2.4 and 3.0 both read them (measured with v2.4.3 and v3.0.5). Each command checks the signature, the
transparency-log entry and that the statement's subject is the digest the tag names; name the image by its linux/amd64
digest (`readystack/<product>@sha256:<digest>`) to check the attestations on the image manifest itself.
`cosign download attestation --predicate-type=<type> <image>` prints them without checking.

## What these attestations are not

- The provenance is not a statement generated by the build platform while it built. ReadyStack writes it afterwards
  from recorded evidence and signs it as its own assertion; it says so in `buildDefinition.internalParameters`.
- None of them claims a SLSA Build track level.
- The VSA records what ReadyStack's own release gate checked at one time. It is not a third-party audit, and a
  vulnerability scan result decays as new vulnerabilities are disclosed: `timeVerified` dates it.
